## Findings

1. Initial guard-enabled isolated test: 15 of the first 17 DNS queries returned SERVFAIL, so the 200-domain run was intentionally stopped. First GitHub cold query timed out at 4.56 s; a later query returned NOERROR and HTTPS 200. Test source was .222 and main had zero BGP routes. Results are `aborted-first.jsonl`; this is not a completed 200-domain test.
2. ROS `/tool fetch` intermittently waits about 1 s despite a packet capture showing TCP handshake and the complete HTTP response in about 2 ms, then ROS delaying its FIN. HTTP 200/204, Connection: close, Content-Length, output=user/none did not reliably eliminate it. File+directory fsync probe on /data/state took 6.5–10.8 ms total, so ordinary idle fsync alone does not explain the wait. Local HTTP is ROS fetching from the container's 9080 control service, not ROS www or the former ROS REST API.
3. Guard batch queue and health snapshot were added to reduce HTTP calls. In a real isolated run, 8-item batches took approximately 2.1–2.4 s. RouterOS successfully fetched a 48,000-byte response. Health uses one bulk snapshot and one index ACK; identity and generations remain checked. Real full-load and failure behavior still need verification.
4. ROS JSON differences: `:find` absent values must be compared by `:typeof ... = "nil"`; deserialize must use `options=json.no-string-conversion` to keep numeric-looking IDs as strings; append JSON objects to arrays by numeric index, otherwise a one-item array can serialize as an object and cause HTTP 400. Scripts now address these issues; validate on real ROS.
5. The second run had repeated SERVFAIL at 5001–5004 ms even with agent confirmation set to 12 s, plugin 14 s and client 25 s. Fixed upstream mosdns entry handler hardcodes a 5 s total deadline. A minimal build-time upstream patch makes entry timeout configurable; default remains 5 s. With explicit timeout, real local UDP/TCP tests of a 5.5–6 s confirmation passed. Guard mode uses entry 20 s/TCP idle 30 s. This is diagnostic headroom, not evidence that clients tolerate production latency.
6. Cancellation and crash cases need special care: a guard operation may have been dispatched/effected even if the ROS ACK says blocked or is lost. Code persists dispatch, cleans orphan guards by matching ownership and checks no BGP/answer, and adds batch/recovery tests. Guard labels must match actual normalized destination, including health/recovery readback. Review and test actual ROS failure paths before use.
7. The final v3 isolated test was interrupted at user request after 4 completed domains, all NOERROR; `aborted-v3.jsonl` is partial and proves neither 200 domains nor acceptable latency. Earlier second run is `aborted-batch.jsonl`. No 200-domain run was completed in this work.
